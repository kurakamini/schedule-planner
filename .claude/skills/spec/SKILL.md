# Spec 駆動開発

引数(任意): 対象の機能名や概要。例: `/spec ユーザー認証`

3 フェーズを順に進める。**各フェーズの成果物はユーザーの承認を得てから次へ進む。**
途中から呼ばれた場合は、既存の docs/spec/ を読んでどのフェーズから再開すべきか判断する。

## フェーズ 1: 要件定義 → docs/spec/requirements.md

1. 既存の docs/spec/ とコードベースを確認し、前提を把握する
2. 不明点は AskUserQuestion でヒアリングする。一度に全部聞かず、決定への影響が大きい順に
3. ユースケースは機能単体(点)でなく、ユーザー体験の流れ全体(線)で描く。
   どこから来て、何をして、どういう状態になって終わるか
4. 機能要件は次の 5 要素で分解する:
   **入力 / 処理 / 出力 / 人間の判断ポイント / 失敗時の戻し方**
5. 背景・目的 / ユースケース / 機能要件 / 非機能要件 / スコープ外 / 未決事項 を書き出す
6. ユーザーのレビューを受け、承認されたらフェーズ 2 へ

## フェーズ 2: 設計 → docs/spec/design.md

1. requirements.md を前提に、アーキテクチャ・データモデル・画面 / API を設計する
2. 大きな技術判断は選択肢と推奨を示してユーザーに確認する
3. 判断した理由を design.md に残す(あとで /task が参照する)
4. 承認されたらフェーズ 3 へ

## フェーズ 3: タスク分割 → docs/spec/tasks.md

1. 設計を「1 タスク = 1〜2 時間で完了し、単体で動作確認できる」粒度に分割する
2. 依存順に並べ、チェックボックス付きで書き出す
3. 各タスクに完了条件を 1 行添える

完了したら「/task で実装を開始できます」と案内する。
