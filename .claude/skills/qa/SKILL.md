# リリース前 QA

対象: docs/spec/tasks.md が(ほぼ)消化された機能一式。

1. requirements.md / design.md を読み、想定される使われ方を把握する
2. 次の観点で**実際に動かして**確認する。机上チェックで済ませない
   - 異常系: 入力が空・不正・巨大なときの挙動。エラーメッセージはユーザーが次の行動を取れる内容か
   - 一貫性: 出力形式・UI 表記・用語がプロジェクト内で統一されているか
   - データ安全: 保存先の誤り、意図しない上書き・削除が起きないか
   - 秘密情報: API キーや個人情報がログ・出力・コミットに混ざっていないか
   - 破壊的操作: 取り消せない操作の前に確認が入るか
3. 自動テストで担保できるものはテストに落とす。担保できない「人間が確認すべき項目」を
   docs/spec/qa.md にチェックリストとして書き出す
4. 見つかった問題は重要度順に報告する。修正方針を提案して承認を得てから直す
   (明白な軽微バグはその場で直して報告でよい)
