# 要件定義: 今夜のスケジュール立案

> `/spec` フェーズ 1 の成果物。承認されるまで設計に進まない。
> 最終更新: 2026-07-14(シーン機能を追加スコープイン)

## 背景・目的

- 帰宅後〜就寝までの時間を YouTube のダラ見で浪費しがちで、これを減らしたい
- 現在は毎晩チャット(AI)に「今からのスケジュールを立てて」と頼む運用を繰り返しており、手間がかかる
- これをアプリ化する。**帰宅後にアプリを開けば最小の操作で「今夜のスケジュール」が立ち、夜の間は「今何をやるべきか」を常に示してくれる**状態がゴール
- やることを終えてから自由時間を「堂々と」取る流れを習慣化する。自由時間は敵ではなく、タスク完了のご褒美として明示する

## ユーザーとユースケース

利用者は本人のみ。Android スマホのブラウザから、自宅 Wi-Fi 経由で PC 上の開発サーバにアクセスして使う(完全ローカル)。

### メインフロー(平日の夜)

1. **【事前・たまに】** ルーチンタスク(夕食 30 分、風呂 30 分、英語 30 分など)を登録しておく。時刻が決まっている予定(22:00〜22:30 の配信視聴など)は固定開始時刻付きで登録できる。普段の就寝時刻(例 24:30)も設定しておく
2. **【帰宅直後】** スマホでアプリを開く → 今夜のプラン作成画面になる。ルーチンタスクが選択済みで並んでいる。今日やらないものを外し、今日だけのタスクがあれば追加し、必要なら並べ替える。就寝時刻は普段の値が入っており、今日だけ変えることもできる
3. 「スケジュール作成」を押す → 現在時刻から就寝時刻までのタイムラインが表示される。固定時刻タスクはその時刻に置かれ、その他のタスクは並び順どおりに隙間へ配置される。全タスク終了後の余りは「自由時間 ◯分」として表示される
4. 就寝までに収まらない場合は警告が出る → どのタスクを外すかは自分で選び、作り直す
5. **【夜の間】** 画面には「今やるタスク」と終了予定時刻が大きく出ている。タスクを終えるたびに完了チェックを付けると、残りタスクが現在時刻から引き直される。前倒しなら自由時間が増え、遅れれば減る(収まらなくなれば再び警告)
6. **【就寝前】** 全タスク完了 → 「自由時間 ◯分」を確認し、堂々と YouTube を見て、就寝時刻に寝る
7. 翌日の夜にアプリを開くと、前夜のプランはリセットされており、再び 2. から始まる

### 具体例

21:10 帰宅、就寝 24:30。選択タスク: 夕食 30 分 → 風呂 30 分 → 英語 30 分(並び順)、固定: 22:00〜22:30 配信視聴。

| 時刻 | 内容 |
|---|---|
| 21:10〜21:40 | 夕食 |
| 21:40〜22:00 | (風呂 30 分は隙間に収まらない → 空き 20 分は自由時間扱い) |
| 22:00〜22:30 | 配信視聴(固定) |
| 22:30〜23:00 | 風呂 |
| 23:00〜23:30 | 英語 |
| 23:30〜24:30 | 自由時間 60 分(+隙間 20 分) |

※ 隙間を詰めたければユーザーが並べ替えで調整する(自動の順序入れ替えはしない。挙動の予測可能性を優先)。

### サブフロー

- 夜の途中でタスクを追加する / 予定していたタスクを外す → いずれも即再計算
- 誤って完了チェックした → チェックを外せば戻り、再計算される

## 機能要件

各機能は「入力 / 処理 / 出力 / 人間の判断ポイント / 失敗時の戻し方」で分解する。

### F1. ルーチンタスク管理

| 要素 | 内容 |
|---|---|
| 入力 | タスク名、所要時間(分)、(任意)固定開始時刻 |
| 処理 | 追加・編集・削除・並べ替え。localStorage に保存 |
| 出力 | ルーチンタスク一覧(プラン作成画面の初期候補になる) |
| 人間の判断 | どれを毎晩の定番にするか |
| 失敗時の戻し方 | 削除は確認ダイアログを挟む。編集・並べ替えはいつでもやり直せる |

### F2. 今夜のプラン作成

| 要素 | 内容 |
|---|---|
| 入力 | 今日やるタスクの選択(ルーチンが初期選択)、当日限りタスクの追加(名前・所要時間・任意の固定時刻)、並べ替え、開始時刻(初期値は現在時刻。当日変更可・再編集時は設定値を保持)、就寝時刻(デフォルト値を当日だけ変更可) |
| 処理 | ①固定時刻タスクをその開始時刻に配置 ②その他タスクを並び順を保ったまま現在時刻から隙間へ配置(隙間に収まらないタスクは固定予定の後ろへ送り、生じた空きは自由時間扱い) ③全タスク終了後〜就寝までを自由時間として算出 |
| 出力 | 開始・終了時刻付きのタイムライン+自由時間の合計 |
| 人間の判断 | 就寝までに収まらないときにどのタスクを外すか(アプリは警告と超過分の明示のみ行い、自動では削らない) |
| 失敗時の戻し方 | 生成後もタスク選択・順序・就寝時刻を変えて何度でも作り直せる |

### F3. 実行トラッキング(完了チェックと再計算)

| 要素 | 内容 |
|---|---|
| 入力 | タスクの完了チェック / チェック解除 / 途中での追加・除外、現在時刻 |
| 処理 | 未完了タスクを「アンカー時刻」から再配置(固定時刻タスクは時刻を維持)。アンカーは完了チェックなど先頭タスクが変わる操作の時点でのみ進み、時間経過やアプリの開き直しでは動かない(開始時刻がずれない)。自由時間を再計算。収まらなくなったら警告 |
| 出力 | 更新されたタイムライン。「今やるタスク」と終了予定時刻の強調表示 |
| 人間の判断 | 遅れが出たときに、タスクを外すか自由時間を削って続けるか |
| 失敗時の戻し方 | チェック解除で完了を取り消すと元のとおり再計算される |

### F4. 設定

| 要素 | 内容 |
|---|---|
| 入力 | デフォルト就寝時刻 |
| 処理 | localStorage に保存 |
| 出力 | プラン作成画面の初期値 |
| 人間の判断 | — |
| 失敗時の戻し方 | いつでも変更可能 |

### F5. 夜の切り替わり(日次リセット)

| 要素 | 内容 |
|---|---|
| 入力 | アプリ起動時の現在日時 |
| 処理 | 「新しい夜」になっていたら前夜のプランを破棄してプラン作成画面から始める |
| 出力 | 当日分のまっさらなプラン作成画面 |
| 人間の判断 | — |
| 失敗時の戻し方 | — |

**重要:** 就寝時刻は深夜 0 時を越えることがある(例 25:00 = 翌 1:00)。0 時を過ぎても同じ「夜」として扱い、プランをリセットしないこと。夜の境界の具体的な判定方法は設計で決める(案: 朝 4 時を境界とする)。

### F6. シーン管理(2026-07-14 追加)

「帰宅後〜就寝」だけでなく、朝(起床〜出発)や休日の日中などでも同じ仕組みを使い分けるため、
「シーン」という上位の階層を導入する。ルーチン・当日のプラン・デフォルト終了時刻はシーンごとに独立する。

| 要素 | 内容 |
|---|---|
| 入力 | シーンの名前、デフォルト終了時刻(夜なら就寝、朝なら出発に相当) |
| 処理 | 追加・リネーム・終了時刻変更・削除。切り替えは画面上部のセレクタで手動のみ。前回選んだシーンを記憶する |
| 出力 | シーンごとのルーチン一覧・当日プラン |
| 人間の判断 | いま立てるのはどのシーンのスケジュールか(自動判定はしない。半自動優先の方針) |
| 失敗時の戻し方 | 削除は確認ダイアログを挟む。最後の 1 シーンは削除できない(シーン 0 件状態を作らない) |

- ルーチンはシーンごとに完全別管理(共有プールは作らない。同名タスクは各シーンに登録する)
- 日次リセット(F5)の朝 4 時境界は全シーン共通(朝のセッションもその日のキーで管理されるだけで支障ない)
- 既存データ(v1)は初回起動時に「夜」シーンとして引き継ぐ

## 非機能要件

- **モバイルファースト**: スマホ縦画面・タッチ操作を第一に設計。片手で完結する操作感
- **完全ローカル**: データは端末のブラウザ(localStorage)にのみ保存。外部送信なし
- **永続性**: リロード・ブラウザ再起動でもルーチン/当夜のプラン/完了状態が保持される。ブラウザのサイトデータ消去で失われることは README に明記する
- **手数最小**: 帰宅後、アプリを開いてからスケジュール完成まで 1 分以内(通常はタスク確認 → 作成ボタンの 2 タップ程度)
- **時刻の扱い**: スケジュールの起点は「開始時刻(アンカー)」。完了チェックなどの操作時点でのみ進み、開き直しではずれない。時計は端末(ブラウザ)に従う
- **時刻入力**: `21:30` に加え `2130` のようなコロンなし 3〜4 桁を受け付ける(Android の数字キーボードにコロンがないため)

## スコープ外(今回つくらない)

- プッシュ通知・アラーム(技術制約: 自宅 Wi-Fi の http 接続ではブラウザの通知 API が使えない。将来ホスティング+PWA 化するなら検討)
- 日別の実績履歴・統計(今夜分の状態のみ保持。履歴は将来拡張)
- タスクの自動並べ替え・隙間埋め最適化(並び順はユーザーが決める)
- ~~朝・休日日中など夜以外のスケジュール~~ → 2026-07-14 に F6(シーン管理)としてスコープイン
- シーンの自動切り替え(時間帯・曜日による推定。切り替えは手動のみ)
- 複数ユーザー・認証・クラウド同期
- カレンダー(Google カレンダー等)連携

## 未決事項(設計フェーズで決める)

- 「夜の境界」の具体的な判定時刻(案: 朝 4 時)
- 固定時刻タスク同士が重なる場合の挙動(登録時に警告する等)
- 開始時刻の丸め(現在時刻そのままか、5 分単位に丸めるか)
- 画面構成の詳細(プラン作成と実行ビューを 1 画面にするか分けるか)
