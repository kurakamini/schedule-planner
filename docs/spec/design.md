# 設計: 今夜のスケジュール立案

> `/spec` フェーズ 2 の成果物。requirements.md を前提とする。
> 最終更新: 2026-07-14(シーン機能 F6 を反映)

## アーキテクチャ概要

React SPA(追加ライブラリなし)。スケジュール計算を純関数として `lib/` に分離し、UI から独立してテストする。

```
src/
  App.tsx                 — 3 タブ切り替え(きょう / ルーチン / 設定)
  types.ts                — 共有型定義
  lib/
    time.ts               — 「夜通算分」の変換・表記・日キー判定
    scheduler.ts          — スケジュール配置の純関数(このアプリの中核)
    storage.ts            — localStorage 読み書き(キー定義・v1→v2 移行・不正データ耐性)
  hooks/
    useNow.ts             — 現在時刻(夜通算分)。30 秒間隔で更新
    useScenes.ts          — シーンの CRUD と選択中シーンの読み書き
    useRoutines.ts        — ルーチンタスクの CRUD(シーンごと)
    useScenePlan.ts       — 当日プランの状態・日次リセット(シーンごと)
  components/
    SceneSwitcher.tsx     — シーン切り替えチップ(きょう / ルーチンタブ共通)
    tonight/              — プラン作成ビュー・実行ビュー・タイムライン
    routines/             — ルーチン管理
    settings/             — 設定(シーン管理・データ全消去)
```

**シーン(2026-07-14 追加)**: 「夜」「朝」「休日」のような時間帯区分。ルーチン・当日プラン・デフォルト終了時刻はシーンごとに独立し、切り替えは手動のみ(選択は記憶)。プランの立案・実行・予定比などの仕組みはシーン非依存で共通。

**データフローの原則: タイムラインの配置結果は保存しない。** 保存するのは「タスクと完了状態とアンカー(起点時刻)」だけで、配置は `scheduler.ts` がアンカーから毎回導出する。

**アンカー方式(2026-07-08 実機フィードバックで変更)**: 配置の起点は現在時刻ではなく `anchorAt`(開始時刻)。アンカーは①作成ビューの「開始時刻」入力(初期値=現在時刻、再編集時は設定値を保持)②完了・外す・追加で先頭タスクが変わった操作の時点、でのみ更新される。時間経過やアプリの開き直しでは動かないため、開始時刻がずれない。現在時刻は NOW カードの残り時間などカウントダウン表示にだけ使う。

## 時刻の扱い(夜通算分)

深夜 0 時越え(要件 F5)を単純に扱うため、内部の時刻はすべて **「その夜の基準日 0:00 からの通算分」(NightMinutes)** で持つ。

- `24:30` → 1470、`25:00`(翌 1:00)→ 1500
- 現在時刻が 0:00〜3:59 のときは前日の夜の続きとみなし +1440 分する(例: 翌 0:30 → 1470)
- **夜の境界は朝 4 時**。`nightKey`(夜の識別子)= 現在時刻から 4 時間引いた日付文字列(例 `"2026-07-08"`)
- 表記はそのまま `24:30` `25:00` 形式(ユーザー確認済み)。入力も `HH:MM` テキストで 24 時以降表記を受け付ける(`0:30` と入力されたら 24:30 に正規化)
- 入力は `2430` のようなコロンなし 3〜4 桁も受け付ける(末尾 2 桁=分)。Android の数字キーボードにコロンがないため(2026-07-08 実機フィードバック)

## データモデル

```ts
// ルーチンタスク(マスタ)
type RoutineTask = {
  id: string          // crypto.randomUUID()
  name: string
  durationMin: number // 所要時間(分)
  fixedStart?: number // 固定開始時刻(夜通算分)。なければ可変タスク
  order: number       // 表示順
}

// 今夜のプランの 1 項目
type PlanItem = {
  id: string
  routineId?: string  // ルーチン由来なら元 ID(当日追加は undefined)
  name: string
  durationMin: number
  fixedStart?: number
  order: number
  included: boolean   // 今日やるか(外す=false。行は残すので戻せる)
  done: boolean
  doneAt?: number     // 完了時刻(夜通算分)
}

// シーン(夜・朝・休日など。2026-07-14 追加)
type Scene = {
  id: string
  name: string        // 例: 夜、朝、休日
  defaultEnd: number  // デフォルト終了時刻(夜通算分)。夜なら就寝、朝なら出発に相当
  order: number       // セレクタの表示順
}

// 当日のプラン全体(シーンごとに 1 つ。旧 TonightPlan)
type ScenePlan = {
  dayKey: string      // "2026-07-08"(朝 4 時境界)。起動時に不一致なら破棄(F5)
  endAt: number       // 当日の終了時刻(夜通算分。旧 bedtime)
  started: boolean    // false=プラン作成ビュー / true=実行ビュー
  anchorAt: number    // スケジュールの起点(開始時刻)。実行中は操作時点でのみ更新(開き直しで不変)。作成ビュー中は開き直し・画面復帰で過去なら現在時刻へ追従
  items: PlanItem[]
  baselineEnds?: Record<string, number> // RTA 予定比の基準タイム(itemId → 予定終了)
}
```

デフォルト終了時刻はシーンが持つため、独立した `Settings` は廃止(v1 の `defaultBedtime` は移行で「夜」シーンの `defaultEnd` になる)。

### localStorage(v2)

| キー | 内容 |
|---|---|
| `sp.v2.scenes` | `Scene[]` |
| `sp.v2.currentSceneId` | 選択中シーンの ID |
| `sp.v2.routines.<sceneId>` | `RoutineTask[]`(シーンごと) |
| `sp.v2.plan.<sceneId>` | `ScenePlan`(シーンごと) |

- 読み込み時に JSON 破損・型不一致は初期値へフォールバック(クラッシュさせない)
- **v1→v2 移行**: 起動時、`sp.v2.scenes` が無ければ実行。v1 データがあれば「夜」シーンを作成(`defaultEnd` = v1 設定の就寝時刻)し、v1 の routines / tonight プラン(`nightKey`→`dayKey`、`bedtime`→`endAt` の変換込み)をそのシーンのキーへ移して v1 キーを削除。v1 も無ければ「夜」(24:30)を新規作成。どちらの場合も `currentSceneId` を「夜」に設定
- シーン削除時は `sp.v2.routines.<id>` / `sp.v2.plan.<id>` も削除する(ゴミを残さない)

## スケジューラ(lib/scheduler.ts)

```ts
type Scheduled = { itemId: string; start: number; end: number }
type Gap = { start: number; end: number }

function buildSchedule(input: {
  items: PlanItem[]   // included かつ未完了のもの
  now: number
  endAt: number       // 終了時刻(夜なら就寝、朝なら出発。旧 bedtime)
}): {
  scheduled: Scheduled[]      // 全項目の配置(超過分も含む)
  gaps: Gap[]                 // 固定予定待ちの空き時間
  freeAfterMin: number        // 最終タスク後〜終了の自由時間(分)
  freeTotalMin: number        // gaps + freeAfterMin
  overflowItemIds: string[]   // 終了時刻を越える項目
  warnings: Warning[]         // 下記
}
```

配置アルゴリズム:

1. `fixedStart` 持ちの項目を時刻順に置く(時刻はユーザー指定を常に尊重)
2. 全項目を `order` 順にたどり、カーソル = `now` から可変項目を詰める:
   - 固定項目を通過したらカーソルをその終了時刻まで進める。**並び順で固定より後ろの可変項目は、固定の前の隙間へ繰り上げない**(2026-07-15 実運用フィードバック: 📌 朝食 7:00 の下に並べた弁当が 6:50 開始で朝食の前に繰り上がってしまった。並び順=実行順とし、固定の前にやりたいものは上に並べる)
   - 可変項目はカーソル以降で、固定予定と重ならない最初の位置に置く。次の固定予定までに収まらなければ後ろへ送る(空きは `gaps` = 自由時間になる)
3. 配置の `end` が `endAt` を越えた項目を `overflowItemIds` に入れる(自動では削らない。外すのはユーザー)
4. 警告(`warnings`): 固定予定同士の重なり / 固定予定の開始時刻超過(現在時刻が過ぎている)/ 終了時刻オーバー

**項目の順序は入れ替えない**(要件どおり。隙間を詰めたければユーザーが並べ替える)。

## 画面設計(3 タブ、下部タブバー)

タブバーは画面下部固定(親指で届く位置)。「きょう」「ルーチン」「設定」。

**シーンセレクタ**: きょうタブとルーチンタブの上部に、シーンを横並びチップで表示(`SceneSwitcher`)。タップで切り替え、選択は `currentSceneId` として保存(次回開いた時も同じシーン)。タブは排他マウントなので選択の共有は localStorage 経由で足りる。シーン切替時はタブの中身を `key={scene.id}` で再マウントし、フック内のシーン切替対応を作り込まない。

文言はシーン汎用に一般化する: 「就寝時刻」→「終了時刻」、「就寝まで◯分」→「終了まで◯分」、見出しは「{シーン名}のプラン / {シーン名}のスケジュール」。

### きょうタブ — 状態 A: プラン作成(`started: false`)

- 開始時刻入力(初期値は現在時刻。再編集時は設定済みの値を保持。未来にすれば帰宅前の仕込みも可)
  - 開き直し・画面復帰の時点で開始時刻が過去になっていたら現在時刻へ追従する(未来の仕込みは保持)
- 終了時刻入力(初期値はシーンのデフォルト終了時刻。今日だけの変更はここで)
- タスクリスト: そのシーンのルーチン全件が選択済みチェックで並ぶ。行 = チェックボックス / 名前 / 所要分 / 固定時刻バッジ / ▲▼ボタン
- 「+ 今日だけのタスク」フォーム(名前・所要分・任意の固定時刻)
- [スケジュールを作成] ボタン → 状態 B へ(`started: true`)

### きょうタブ — 状態 B: 実行ビュー(`started: true`)

- ヘッダ: 終了まで残り◯分 / 自由時間 合計◯分 / 予定比 ±◯分(下記)
- **NOW カード**: 今やるタスク名 + 終了予定時刻 + [完了] 大ボタン(このアプリの主役)
- タイムライン: 完了済み(グレー・完了時刻表示・予定比 ±◯分)→ 現在(強調)→ 以降(開始〜終了)。固定予定は 📌 印、空きは「自由時間 ◯分」行として表示
- **予定比(RTA タイマー風の ± 表示)**: 開始時に各タスクの予定終了時刻を基準タイム(`baselineEnds`)として凍結し、実績と比べて早ければ緑 `-◯分`、遅れれば赤 `+◯分`、同着はグレー `±0分`(lib/rta.ts)
  - 完了ごと = 完了時刻 − そのタスクの基準終了。全体 = **最後に完了したタスク時点のズレ(スプリット差)**
  - 全体を終了見込みベースにしない理由: 固定予定(📌)があると見込みが釘付けされ、早く完了しても緑が出ず「遅れのプラスしか反映されない」体感になるため(2026-07-14 実運用フィードバック)。収まるかどうかの見込みは「終了までに◯分収まりません」警告が別で担う
  - 完了による再配置(アンカー移動)はタイムラインだけを動かし、基準タイムは動かさない(ズレを測る物差しとして固定)
  - 実行中に追加したタスク(基準なし)は行の ± を出さず、全体のスプリットにも数えない(その影響は以降の完了時点のズレとして自然に現れる)
  - 再編集からの再開始では未完了分の基準だけ引き直し、完了済みの基準は保持する
- 収まらないとき: 上部に警告バナー「終了までに ◯分 収まりません」+ 超過タスクを赤表示。各行のメニューから「外す」(included=false)
- フッタ: [タスク追加] [プランを編集](状態 A へ戻る。選択・完了状態は保持)
- 全タスク完了時: 「おつかれさま 🎉 自由時間 ◯分」を大きく表示(ご褒美画面)
- 誤操作の戻し: 完了チェックの解除、外したタスクの復帰(作成ビューで再チェック)

### ルーチンタブ

- 上部にシーンセレクタ。一覧・フォームは選択中シーンのルーチンのみを扱う
- 一覧: 名前 / 所要分 / 固定時刻 / ▲▼ / 編集 / 削除(削除は確認ダイアログ)
- 追加・編集フォーム(名前・所要分・任意の固定時刻)

### 設定タブ

- **シーン管理**: シーンの一覧(名前・デフォルト終了時刻)、追加・リネーム・終了時刻変更・削除
  - 削除は確認付きで、そのシーンのルーチン・当日プランも一緒に消える旨を表示
  - 最後の 1 シーンは削除不可(ボタンを無効化)
- データ全消去ボタン(確認 2 段階。localStorage を初期化 → 初期シーン「夜」だけの状態に戻る)

## 主要な技術判断と理由

| 判断 | 理由 |
|---|---|
| 追加ライブラリなし(ルータ・状態管理・DnD 不使用) | 規模が小さく React 標準で足りる。依存を減らし保守を軽くする |
| 時刻は「夜通算分」で統一 | 深夜 0 時越え(24:30 就寝等)の比較・計算が単純な整数演算になる |
| 配置結果は導出値(保存しない) | 保存は items と完了状態のみ。「再計算」という状態遷移が消え、バグの温床を断つ |
| スケジューラを純関数に分離 | 中核ロジックを UI なしでユニットテストできる |
| 夜境界は朝 4 時固定 | 就寝 25〜27 時台までカバーし、実装が単純(要件の未決事項を確定) |
| 外す=`included: false`(行削除しない) | 「失敗時の戻し方」要件(復帰可能)を素直に満たす |
| 並べ替えは▲▼ボタン | スマホで確実に動き、ライブラリ不要(ユーザー確認済み) |
| 開始時刻の丸めなし・24:30 表記 | ユーザー確認済み(要件の未決事項を確定) |
| シーンは自由作成・手動切替・ルーチン完全別管理 | ユーザー確認済み(2026-07-14)。自動切替や共有プールは複雑さに見合わない |
| シーン切替は `key={scene.id}` の再マウント | フック群をシーン非依存のまま保てる。切替頻度は低く再マウントのコストは無視できる |
